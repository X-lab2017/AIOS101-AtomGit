# ADR-0003：理解机制先于核验清单

日期：2026-10-29；状态：本轮修订采用。

## 问题

第四至六章虽可构建上线，但主线逐渐变成反复判断“未实测不能说成功”；第六章核心用作者编写的日志，却要求从实际任务记录学习。大量合规提醒、模板和固定数量图件，挤压了机制解释。自动测试甚至强制第六章七节、三图、十文件，错误地把编排数量当成质量。

## 决定

- 每章先回答一个新的机制问题，再给一次能观察变化的任务：参数怎样选、输入怎样影响生成、反馈怎样改变下一步。
- 保留必要的事实/模拟区分，集中在活动入口与来源；不在每节重复。
- 实际模型输出与实际 DSH 任务是对应目标的证据。无接入者可先演练，但进度保留待补，不把阅读作者例子等同目标完成。
- 继承已核验导览，不重新植入前章已纠正的错误。第五章候选延续至第六章实际文件修改。
- 图必须展示正文关系或变化；不以泛化图书馆、装饰插画和全文转框图填数量。保留统一色系、图号与来源。
- 自动检查验证正本、必要输入、准确算术、提示词差异、归档字节与图件哈希，不规定章节恰好多少节/图/文件。

## 验收

编辑复核、独立内容审阅、静态图文检查、浏览器公开页复验分别留证。构建通过不是内容审定；无真实环境不能编造运行或读者反馈。第七章保持提纲，本轮只回头修订。
