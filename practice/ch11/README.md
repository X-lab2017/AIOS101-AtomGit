# 第十一章材料包：一次改进怎样成为协作

> 状态：review
> 版本：0.2.0

先读差异，再把方法用于真实作品。这里的文件是作者编写的教学情境，不是真实 Issue、PR 或同伴反馈。

## 先做一次差异演练

情境：导览已经放在 `examples/works/guide.md`，入口应从 `examples` 所在目录打开。

1. 用文本编辑器打开 [before.txt](examples/before.txt) 和 [candidate.txt](examples/candidate.txt)。找出链接问题的修复，也找出一项不应接受的说法。
2. 核对 [实际导览](examples/works/guide.md) 的位置。说明入口文字和路径各解决什么问题。
3. 再打开 [reference.txt](examples/reference.txt) 与 [参考反馈](examples/feedback.md)。需要实际点链接时，将参考文本复制成 `examples/README.md` 后打开 Markdown 预览；它是自己的演练文件，无须公开发给上游。

`.txt` 文件保留原样文字，避免错误示例在课程页中成为误导性的可点击入口。演练不要求安装程序或执行命令。

## 再处理一个真实问题

选择同伴、课程或合适项目，先读协作规则和既有讨论。用 [AtomGit 协作操作卡](atomgit-collaboration.md) 进行问题反馈或文档修订。若进行 PR，确认源分支、目标分支、实际差异与检查结果。没有真实对象时，可在个人仓库演练，但不能记为他人评审或已帮助上游。

已有观察站的协作页可直接记录；需要支架时用 [work/contribution.md](work/contribution.md)。自己收到反馈时据实回应，没有收到就保持待发生。回到[第十一章](../../textbook/chapters/CH11.md)，再进入[第十二章](../../textbook/chapters/CH12.md)。
