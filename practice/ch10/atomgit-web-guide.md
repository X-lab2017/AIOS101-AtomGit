# AtomGit 浏览器操作卡

文档核对日期：2026-10-30。适用任务：保存和分享轻量文档观察站。依据为官方帮助，尚未在课程账号中逐步实操；部分官方说明和截图仍出现 GitCode 名称。以当前页面、账号权限和官方更新为准。

## 1. 进入自己的项目

已有观察站仓库就继续使用。没有时，登录 AtomGit，在“新建”中寻找“新建项目”，选择代码仓，填写名称和项目路径，确认公开或私密范围，可以初始化 README。模型仓和数据集仓不用于替代本次文档仓。名称、验证要求与可用功能按平台当前提示处理。

官方入口：[快速入门](https://docs.atomgit.com/docs/start/quick/)。若没有创建权限，先向课程提供者确认教学空间；不能用别人的账号绕过权限。无账号阶段可以继续本地整理。

## 2. 保存作品与入口

在项目代码页寻找“新增文件”；为单文件版创建 `station.md`，粘贴已经核验的内容，检查后提交。再编辑 `README.md`，加入说明及 `[打开观察站](station.md)` 入口。已有文件就编辑对应文件，不覆盖别人的修改。

若要放在子目录，官方在线编辑支持在文件名中填写路径加文件名，例如 `works/station.md`。此时 README 的链接也要改为相同路径。图片通过当前页面可用的上传方式处理；不熟悉附件操作时可先交付纯文本文档，不把不明图片网址硬填进去。

编辑后寻找“提交修改”，填写改动目的，确认提交位置。文件创建、修改和删除都会进入历史；在共享仓库遇到分支保护或审核要求时按规则提交，不能为了完成作业关闭保护。浏览器编辑无需先运行 Git 命令。

官方依据：[文件的在线操作](https://docs.atomgit.com/docs/help/home/org_project/project_manage/file_operations/online_file_operations/)。

## 3. 找到本次版本

保存后重新打开文件检查内容。通过项目的提交历史或提交数入口，找到自己的说明，打开本次提交，查看改动。保存当前仓库入口和这次提交页面地址；前者供日常阅读，后者供版本回查。不要手工猜测提交链接。

官方依据：[提交](https://docs.atomgit.com/docs/help/home/org_project/project_manage/file_operations/commit/)。

## 4. 检查别人能否使用

从 README 的作品入口走一遍，确认内容、附件、来源与返回路径。公开项目可用未登录状态检查访问；限成员项目在允许的范围内检查对方权限。不要为测试临时公开私人内容。

记录实际可见性和一次使用检查。没有同伴时写“作者自查”，收到真实反馈后再补。上传文件、完成使用检查、获得他人反馈是不同进度。

## 5. 遇到界面差异

找不到某按钮时先看页面是否处于自己的项目、是否有编辑权限、所选文件和分支是否正确，再按上方官方链接查当前说明。不要用删除仓库重建解决普通路径问题；不要向 AI 粘贴登录密码或令牌。
