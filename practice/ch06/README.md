# 第六章材料包：看清一次任务怎样推进

> 状态：review
> 版本：0.2.0

延续已有 DSH 项目导览，追踪材料读取、文字生成、文件写入和人的检查。核心路径只读教学记录，不需账号、付费或编程；真实 DSH 任务另列为选做。两条路径都要诚实标明完成范围。

## 先准备，再选择路径

解压后得到 `ch06`，放进已有观察站，与 `ch05` 并列。已有同名文件夹时先比较，勿覆盖个人记录。`.md` 与 `.txt` 可用普通文本编辑器打开，也可在纸上记录后保存照片。

本次不重建观察站、不替换旧导览。先阅读 `materials/guide-before.md`。有自己的导览时，可将其**副本**放到这个文件位置，保留原作；记录副本来自哪一版，并保留与本任务有关的来源。若原作还有本包未提供的事实，先把练习范围限定为有 A、B 依据的段落，不要求工具补猜。没有导览时，直接使用标为教学设计的预置原稿。

## 核心路径：先读记录，再判断

1. 阅读三份 `materials` 文件及 `prompt.txt`，圈出任务目标和允许范围：读取三份输入、创建一个新候选，成功创建后可读回该候选；不读取其他 work 记录。
2. 打开 `examples/task-trace.md`，按 T1—T9 逐行判断：读取、生成、执行请求、实际执行还是人的检查？这一行处于什么状态？
3. 填写 `work/task-record.md`，至少指出一次失败、一次拒绝、一次不能仅凭文字确认的完成声明。先独立作答，再读 `examples/self-check.md`。
4. 给原导览提出一处修订，说明依据；记录“阅读教学轨迹，未实际运行 DSH”。本路径不产生真实工具日志，也不证明 DSH 已成功修改文件。

## 选做：在已有可用 DSH 中追踪自己的任务

教学方应先核实实际版本、模型接入、额度、权限和练习环境；优先准备专用环境，并备份可访问的文件。学习者只用无敏感信息的材料副本，不把重要文件交给实验。固定版安全说明提醒：DSH 属于未经安全审计的实验性开发者预览，审批和沙箱不构成安全保证，详见 `sources.md`。

只在已经接通模型、确认可用额度且能够选择工作区时进行；本包不要求安装或临时付费。准备尚未完成就保留核心阅读记录，实际运行记为待做。当前版本的入口与权限提示可能不同，先对照官方说明，见 `sources.md`。

1. 将 **ch06 文件夹本身**作为本次工作区；这样提示词中的 `materials/source-a.md` 才对应正确位置。不要授权整个个人资料目录。确认 `work/guide-candidate.md` 不存在；存在时先为本次任务选择新名称，并同步修改提示词与记录，勿覆盖。
2. 发送 `prompt.txt`。只提供其中指定的三份材料，不将教学轨迹或反馈作为本次任务材料。若应用不能限制目录访问，记录限制，并仅使用无敏感信息的练习副本。
3. 观察可见工具请求、实际返回与审批范围，保留必要证据。涉及额外联网、安装、发布或覆盖原稿的请求不属于本任务；暂停并拒绝，不为完成练习扩大权限。
4. 任务结束或受阻后，填写 `work/run-evidence.md`，再用 `work/task-record.md` 总结。找到候选文件并打开，对照原稿和材料检查；若自己手工保存，要记明由人执行，不能记作 DSH 写入成功。

提示词中的限制不是技术隔离保证；仍需选择恰当工作区和权限设置，并核对实际动作。不给工具密钥、个人隐私或无关目录，也不公开含敏感信息的日志。

## 完成标准

留下一份带状态的任务记录，区分“打算做、请求做、确实发生、已检查”，指出一处人的授权判断和一项未确认信息。阅读路径完成的是轨迹分析；真实路径还需留下实际条件、可见证据与产物核验，不要求每次成功。失败或受阻而记录清楚，同样可以用来分析机制。
