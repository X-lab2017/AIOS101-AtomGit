## 打开一个开源项目：从项目全貌到材料与协作

核心问题：怎样读懂一个项目的全貌，并为自己的研究找到合适的材料与参与方向？

学习成果：LO1, LO2, LO3

前置知识与材料：第一章基础概念与一页简报；也可使用书中参考材料；无需编程先修

### 学习目标

- 从目的、成果、材料和协作四个方面解释项目，区分项目、仓库与平台
- 按问题选择 README、文件目录、研究说明、版本记录与贡献指南，解释它们各自的用途
- 结合真实项目说明不同成果类型与社区参与方式，区分来源记载、个人判断和未解决的问题
- 完成有依据的项目档案，修订第一章简报，并提出一个可以继续研究的小问题

### 内容路线

1. 以 OpenDipper 认识项目的目的、成果、材料与协作
2. 区分项目、仓库与平台，按问题阅读 README
3. 辨认程序、数据、文档、检查与权利说明的不同职责
4. 比较模型、工具、研究与内容项目的材料需求
5. 通过 OD 内容任务与 DSH 对照理解社区及 Issue、PR
6. 记录来源、版本和日期，区分说明、观察与判断
7. 建立主项目档案，形成短对照，修订简报并提出研究问题

### 贯穿实践与评价

M02：围绕 OpenDipper 建立主项目档案，以 R1、DSH 或本教材作短对照，修订第一章简报并提出下一步研究问题。

学习证据：有来源的项目全貌与材料选择、一项协作解释、简短对照、一次有理由的修订和一个后续问题

## 历史写作设计 · 0.2.0

本章承接第一章导览：从使用给定材料，转向亲自寻找、阅读和记录官方材料。核心任务只需浏览与编辑文本，无需安装 DSH、下载模型、调用付费服务或提交社区内容。

### 正文结构

- 2.1 从名字到可以确认的官方入口；分别选定 DeepSeek-R1 模型和 DSH 工具，不用宽泛品牌名代替对象。
- 2.2 带着问题读 README、模型说明与文件目录；解释模型权重、模型卡、配置和运行说明的用途，不展开架构或训练细节。
- 2.3 到 README 之外看文档、贡献说明和讨论；以 DSH 固定版本的贡献入口说明为例，避免默认所有项目都通过 Issue/PR 接收贡献。
- 2.4 区分模型、软件、服务与社区；明确代码仓库、模型文件、运行工具、在线入口之间的区别。
- 2.5 将项目自述、阅读/运行观察和推断分开；保留暂未确认的条件。
- 2.6 版本、日期、可定位的来源；不把 main 分支、文档提交、应用版本与实际服务模型混为一谈。
- 2.7 建立双对象简明档案，提出一个可以继续探究的问题；自查与反馈。

### 配套材料与证据

提供同一观察站内可新增的 ch02 子目录：来源导航、固定版本材料摘记、空白双对象档案、明确标为编写者参考的示例。实际访问原站与仅阅读课程材料分别记录；模型无需下载。允许 AI 协助翻译/整理，但不能把其补写当原文，也不要求必须使用 AI 才能完成阅读任务。

沿用 R1 README 固定提交 0cf78561f1d51c84a21b2190626b21116d5c68bb 和 DSH 固定提交 f3803c96974ad4a94195fb97e5c637e9c2a3afe3；官方发布页确认入口，模型文件目录为额外观察来源。访问日期和原始链接随材料登记。

### 图件需求

- AG-02-01：从入口走进开放工坊。手绘科技出版插画，以说明牌、资料架、工作台和讨论区构成概念隐喻；不冒充真实软件架构或真实实验室。
- AG-02-02：读项目说明时先找什么。优先使用 DSH 固定版本中文 README 的实际浏览器截图，精确标注观察位置；不生成伪界面。
- AG-02-03：一条说法的记录边界。原生 SVG 排版，以有来源的具体例子区分项目说明、我的观察、待验证判断。文字完整可放大。

正文约 4,500—6,000 个汉字；图号、图题、来源和状态统一。标记 review 等待维护者评审，不能把资料阅读、部署或模板下载写成实际 DSH 运行与真人试学。
